# Standalone Plagiarism/AI-Check Tab

## Date
2026-08-05

## PRD Section
§3.3 (plagiarism/AI-detection), user-requested addition beyond the original epic breakdown

## Summary
The user asked for the plagiarism/AI-fingerprint pre-check (TASK-E07-2, already wired into
generation per TASK-INT-3) to also be usable as a **standalone** feature — checking arbitrary,
already-written text (not necessarily generated by this platform) independent of any
project/chapter. Built as a fixed API contract, then two agents in parallel against it.

**Backend (TASK-INT-4):** New `plagiarism/router.py`, `POST /plagiarism/check` — stateless,
no auth/project/chapter association, reuses the exact same `run_precheck` function the generation
endpoint calls. Request: `{"text": string, "source_excerpts"?: string[]}` (`text` required,
`min_length=1`); response: the same `PlagiarismCheckResult` shape (`plagiarism_score`,
`ai_fingerprint_score`, `flagged`, `reasons`) already used elsewhere.

**Frontend (TASK-INT-5):** New "Plagiarism Check" tab, sibling to "Workspace", added via a small
`AuthenticatedApp` wrapper with local tab-switch state (no routing library, per ADR-0008 — this
codebase stays Context+hooks-only). `PlagiarismCheckPanel` is fully self-contained (its own
`useState` for text/result/loading/error — no shared context needed, since it isn't tied to any
project). Onboarding gating (auth + institution selection) is unchanged; the tab bar only appears
once a user is past it.

## Residual Risks
- Same heuristic-scoring caveats as TASK-E07-2 (n-gram overlap, sentence-uniformity proxy — not a
  real plagiarism/AI-detection API). A self-check user should treat results as a signal, not a
  verdict, same as the generation-pipeline's internal use of the same function.
- No rate-limiting on this endpoint — acceptable for now since it's pure CPU-bound scoring with
  no LLM call, but worth revisiting if usage patterns ever suggest abuse.
